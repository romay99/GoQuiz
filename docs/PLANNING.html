1. 제품 개요

lichess의 체스 퍼즐처럼, 바둑의 사활(life & death) 문제를 랜덤으로 무한히 풀 수 있는 안드로이드 앱. 사용자가 바둑판 에디터로 직접 문제를 올리고, 서로의 문제를 풀며, 좋다/나쁘다 평가와 시도·정답 통계로 난이도가 자동으로 매겨진다.

4. 데이터 모델 (Firestore)

RDB → NoSQL 전환 3원칙
① JOIN 없음 → 필요한 값은 문서에 중복 저장(역정규화)
② COUNT 비쌈 → attempts/solves는 카운터 필드로 미리 집계
③ 읽은 문서 수만큼 과금 → 목록 읽기 비용 의식
problems/{problemId}
  sgf:        "(;GM[1]FF[4]SZ[9];B[ef]...)"   // 문제 + 정해 트리
  boardSize:  9 | 13
  toPlay:     "B" | "W"
  title:      "흑 선, 사는 문제"
  authorId, authorName        // authorName은 역정규화(복사)
  createdAt
  random:     0.48            // 랜덤 출제용
  // 카운터 (Cloud Functions만 갱신)
  attempts, solves, upvotes, downvotes
  solveRate                   // solves/attempts, 난이도 표시

users/{uid}
  displayName, photoURL, createdAt, solvedCount

users/{uid}/attempts/{problemId}    // 중복 집계 방지
  result: "solved" | "failed"
  vote:   "up" | "down" | null
  attemptedAt

핵심 설계 포인트

  • 랜덤 출제: Firestore엔 ORDER BY RANDOM()이 없음 → 각 문제에 random(0~1) 필드를 두고 where('random','>=', Math.random()) orderBy('random') limit(1), 없으면 처음으로 wrap.
  • 통계 조작 방지: attempts/solves/vote는 클라가 직접 못 올림. Callable Function이 users/{uid}/attempts/{problemId} 존재 여부로 첫 시도 확인 후 트랜잭션으로 카운터 갱신.
  • 보안 규칙(출시 전 필수): problems 읽기=전체 / 생성=로그인(authorId==uid) / 카운터 수정=차단. users=본인만.

5. 정해 수순 판정기 (코어 로직)

우리가 유일하게 직접 구현하는 핵심. 라이브러리(규칙·파싱) 위에 올라가는 순수 퀴즈 로직.

SGF 문제 저작 규칙

  1. 루트 = 초기 배치(AB/AW) + 선(PL). 착수 없음.
  2. 이후 노드는 푸는 사람 색 → 상대 색 번갈아 등장.
  3. 푸는 사람 차례의 children = 인정하는 정답 수들 (복수면 복수정답).
  4. 상대 차례의 children = 상대 응수 (MVP: 1개만 가정).
  5. leaf 도달 = 성공. 틀린 수는 트리에 없음 → 자동 오답.
(;GM[1]FF[4]SZ[9]
   AB[cc][dc][ec]     // 흑 초기 배치
   AW[cd][dd][ed]     // 백 초기 배치
   PL[B]              // 흑 선 = 푸는 사람
 ;B[bb]               // 정해 1수
   ;W[ab]             // 상대 자동 응수
     ;B[ba]           // 정해 2수 → leaf면 성공
)

테스트 케이스 (Phase 2 목표)

#시나리오기대
1한 수로 정답 (leaf 직행)solved
2트리에 없는 수failed
3복수 정답 (children 2개)둘 다 solved
4다단계: 정해1→응수→정해2단계별 playing→solved
5상대 자동응수 좌표 반환opponentMove 정확
6따냄 발생 수board에서 돌 제거
7실패 후 추가 입력무시(failed 유지)
8백 선(PL[W])solverSign=-1 정상
